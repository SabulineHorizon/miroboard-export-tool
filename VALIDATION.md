electron-builder 26.18.1 and Playwright 1.65.0. No real Miro credentials used.

- Passed: all 171 tests in 10 files, TypeScript, CLI build and `--help`,
  desktop build, development GUI integration, and newly packaged Windows GUI
  integration against the local fixture. Both integrations passed all formats,
  URL/ID input, token clearing, sanitized errors, window security settings and
  the `gridSize: 10` compatibility checks.
- Passed: `npm run pack:win`; packaged ASAR inspection found only desktop
  resources, package metadata and production dependencies, with no environment
  files, test outputs, local notes or caches.
- Portable packaging reached final output but the existing executable was locked
  by a running application. That application was left open. A separately named
  `release/Miro-Board-Exporter-0.1.0-publication-check.exe` was successfully built
  from the tested `win-unpacked` application using `--prepackaged`, an artifact
  name override and `--config.compression=store`. The builder reused the archive
  generated by the default portable build. Normal launch of this new wrapper
  has not been manually checked; see the earlier wrapper checks below.
- `npm audit --omit=dev`: zero findings. After compatible `npm audit fix`
  updates, the full audit reports 16 affected development/tooling packages
  (9 high, 7 moderate), including transitive Vite, picomatch, minimatch and glob
  findings. No forced major changes, overrides or tooling downgrades were made.
  These findings remain follow-up work; the older audit result below is historical.
- Publication audit covered tracked/untracked source, all 24 reachable commits
  (73 distinct historical file blobs), relevant ignored generated text, npm logs,
  test fixtures, environment/credential filenames and packaged file inventory.
  No credentials or private board exports were identified. Dummy test tokens

  paths and remain excluded. Dependency binaries/caches are not exhaustively
  secret-scanned and are not staged.
- An inherited hardcoded board ID in `scripts/inspect-board.mjs` was replaced
  with an explicit command argument. That ID remains in upstream history; it is
  an identifier, not an authentication credential. History was not rewritten.
- Expanded ignore rules for environment variants (retaining `.env.example`),
  logs, test reports and local discovery notes. Generated outputs, dependencies,
  executables, test screenshots and caches remain excluded. README now explains

The sandbox temporary directory caused an initial Vitest cache rename failure;
rerunning with TEMP/TMP under ignored `test-output/tmp` passed. Electron tests
and network-dependent packaging/auditing required execution outside the sandbox.

## Earlier desktop validation — November 13, 2026

Environment: Windows 11 x64, Electron 45.3.2, electron-builder 26.18.1,
Playwright 1.65.0. No real OAuth token was used.

Passed:

- 171 Vitest tests across 10 files, including generator `gridSize: 10`, shared
  pipeline output, URL/ID validation, settings validation and safe errors.
- TypeScript `tsc --noEmit`; original CLI build and `--help`; `git diff --check`.
- Development GUI, packaged `win-unpacked` GUI, and application extracted by the
  single-file portable launcher: offline integration checks exported a text item
  into all formats, accepted both a URL and ID, cleared the token input, checked
  output-folder dispatch, and displayed a sanitized 401 response. The same test
  exercised the original compiled CLI with all formats. All emitted standard

- Runtime preferences: Node integration false, context isolation true, sandbox
  true, renderer `require` undefined, no renderer JavaScript errors observed.
- Normal portable executable launch displayed the app; Browse opened a real
  native Windows folder dialog. Native selection completion and Explorer opening
  were not automated; their dispatch was verified using test replacements.
- SHA256 of the portable-extracted and `win-unpacked` `app.asar` matched:
  `18EB870C2D6512E90D6932693006131135F13EE51A249B670ADAD7F3707B794B`.
- `npm audit --omit=dev`: zero reported vulnerabilities after compatible lockfile
  updates. Full audit still reports six moderate findings in packaging tooling;
  npm's proposed fix requires a breaking electron-builder downgrade, not applied.

Release: `release/Miro-Board-Exporter-0.1.0-portable.exe`, 111,221,833 bytes.
Alternative: copy the complete `release/win-unpacked` folder.

Automation limitation: directly passing the portable wrapper to Playwright's
Electron launcher timed out after 60 seconds. A normal launch worked. Running
the integration check against its temporary extracted application passed. This
is not evidence that direct Playwright wrapper attachment works on other hosts.

Remaining manual verification: a clean Windows machine without Node/npm; live
Miro board access, real image/document downloads, and import into current
tldraw.com. Manual checks should cover board access, asset downloads, and opening the output
in the destination app. The release is unsigned and
uses the default Electron icon. Matching output filenames are overwritten and
failed exports can leave partial files. Standard `.tldr` assets keep the existing
remote-link behavior, so downloading images does not guarantee offline images.

Implementation preserves the pre-existing tldraw source correction and uses the
existing CLI/extractor/generators. Existing lockfile changes were carried forward
through dependency installation; no user files were reset or committed.
